# 🎯 CH01 — Interview Questions

> This chapter focuses on **Project Planning & Vision**. These questions are commonly asked in Software Engineering, Product Engineering, and System Design interviews.

---

# 📚 Beginner Level

---

## Q1. What is Software Engineering?

### Answer

Software Engineering is the systematic process of designing, developing, testing, deploying, and maintaining software using engineering principles.

Unlike programming, Software Engineering focuses on the entire software lifecycle rather than just writing code.

It includes:

- Planning
- Requirement Analysis
- Design
- Development
- Testing
- Deployment
- Maintenance

---

## Q2. What is a Software Project?

### Answer

A software project is a temporary effort undertaken to build a software product that solves a specific problem.

Examples:

- CartWise
- Instagram
- Spotify
- Amazon

Every software project has:

- Objectives
- Timeline
- Scope
- Resources
- Deliverables

---

## Q3. What is Project Planning?

### Answer

Project Planning is the process of defining:

- Goals
- Scope
- Timeline
- Resources
- Technology Stack
- Development Strategy

before implementation begins.

Planning reduces uncertainty and improves project success.

---

## Q4. Why is Project Planning important?

### Answer

Without planning, software projects often suffer from:

- Unclear requirements
- Scope creep
- Poor architecture
- Increased technical debt
- Missed deadlines
- Cost overruns

Planning provides a clear direction for development.

---

## Q5. What is Product Vision?

### Answer

A Product Vision is a long-term statement describing what a software product aims to become.

It acts as the guiding principle for all engineering decisions.

Example:

The vision of CartWise is to become an AI-powered shopping assistant that helps users make better purchasing decisions.

---

## Q6. What is Project Scope?

### Answer

Project Scope defines what is included and excluded from the current project.

Example:

Current CartWise Scope:

- Homepage
- Routing
- Shared Components

Future Scope:

- Backend
- Authentication
- AI Integration

A clearly defined scope prevents unnecessary expansion.

---

## Q7. What is Scope Creep?

### Answer

Scope creep is the uncontrolled addition of features without proper planning.

Example:

Adding Chat functionality while the Search feature is still incomplete.

Effects:

- Increased complexity
- Delays
- Budget overruns
- Technical debt

---

## Q8. What is Documentation?

### Answer

Documentation explains the purpose, architecture, implementation, and usage of software.

Good documentation improves:

- Maintainability
- Team Collaboration
- Onboarding
- Knowledge Sharing

---

## Q9. Why is Documentation important?

### Answer

Documentation ensures that software can be understood and maintained long after it has been developed.

Benefits include:

- Easier debugging
- Faster onboarding
- Better collaboration
- Reduced dependency on individual developers

---

## Q10. What problem does CartWise solve?

### Answer

CartWise simplifies online shopping by allowing users to compare:

- Prices
- Specifications
- Ratings
- Reviews

from multiple stores within a single platform.

# 🚀 Intermediate Level

---

## Q11. Why shouldn't developers start coding immediately?

### Answer

Jumping directly into coding often leads to:

- Poor architecture
- Frequent rewrites
- Inconsistent implementation
- Higher maintenance costs

Planning first helps define the correct direction.

---

## Q12. What is Technical Debt?

### Answer

Technical Debt is the future cost of taking shortcuts during development.

Examples include:

- Poor folder structure
- Duplicate code
- Missing documentation
- Weak architecture

Reducing technical debt improves long-term maintainability.

---

## Q13. What is Incremental Development?

### Answer

Incremental Development means building software feature by feature instead of all at once.

CartWise follows this approach by implementing one chapter at a time.

---

## Q14. What is Maintainability?

### Answer

Maintainability refers to how easily software can be modified, improved, or fixed.

Factors affecting maintainability:

- Clean code
- Modular design
- Documentation
- Consistent architecture

---

## Q15. What is Scalability?

### Answer

Scalability is the ability of software to continue performing efficiently as the number of users or data increases.

A scalable system can grow without requiring major redesign.

---

## Q16. Difference between Programming and Software Engineering?

### Answer

Programming focuses on writing code.

Software Engineering focuses on building complete software systems including planning, architecture, testing, deployment, and maintenance.

---

## Q17. What is a Technology Stack?

### Answer

A Technology Stack is the collection of tools, frameworks, and technologies used to build software.

Current CartWise Stack:

- React
- TypeScript
- Vite
- Tailwind CSS

Future additions:

- Spring Boot
- PostgreSQL
- Docker

---

## Q18. Why was CartWise built using an incremental approach?

### Answer

Incremental development allows:

- Better learning
- Easier debugging
- Continuous improvement
- Better documentation
- Lower development risk

---

## Q19. What makes good software documentation?

### Answer

Good documentation should be:

- Accurate
- Updated
- Beginner-friendly
- Well structured
- Easy to navigate
- Technically correct

---

## Q20. What is the difference between Vision and Scope?

### Answer

Vision describes the long-term destination.

Scope describes what is currently being built.

Vision changes rarely.

Scope evolves with every release.

# 🔥 Advanced Level

---

## Q21. How does planning reduce technical debt?

### Answer

Planning helps establish:

- Proper architecture
- Consistent coding standards
- Reusable components
- Clear responsibilities

This reduces future rewrites and maintenance costs.

---

## Q22. What are non-functional requirements?

### Answer

Non-functional requirements describe how software should behave.

Examples:

- Performance
- Reliability
- Security
- Scalability
- Maintainability

---

## Q23. Why is software architecture discussed before implementation?

### Answer

Architecture determines how software components interact.

Changing architecture after implementation is expensive.

Planning it early reduces redesign costs.

---

## Q24. How does documentation improve software quality?

### Answer

Documentation:

- Preserves knowledge
- Improves onboarding
- Simplifies debugging
- Encourages consistency
- Helps future maintenance

---

## Q25. Why should a learning project follow production standards?

### Answer

Because production practices teach:

- Clean Architecture
- Code Quality
- Testing
- Scalability
- Documentation

These skills transfer directly to professional software development.

# 🏗️ System Design & Real-world Questions

---

## Q26. If CartWise grows to millions of users, what planning decisions made today will still matter?

### Answer

Examples include:

- Modular Architecture
- Feature-first Folder Structure
- Documentation
- Reusable Components
- API-first Thinking

These decisions make scaling significantly easier.

---

## Q27. Why should documentation evolve with implementation?

### Answer

If documentation is written only at the end, it often becomes outdated.

Keeping documentation synchronized ensures it accurately reflects the current state of the project.

---

## Q28. How would large companies approach project planning?

### Answer

Companies such as Google, Microsoft, Amazon, and Netflix typically begin with:

- Product Requirement Documents (PRDs)
- Architecture Reviews
- Design Documents
- Risk Assessments
- Milestone Planning

Only after approval does implementation begin.

---

## Q29. What is the biggest mistake students make while building projects?

### Answer

Many students focus only on writing code.

Professional engineers focus equally on:

- Planning
- Architecture
- Documentation
- Testing
- Maintainability

These aspects determine long-term project quality.

---

It includes:
